# Quant Astro

本地运行的排盘程序，包含印度占星（Vedic / KP）和西方占星两个体系，两个体系共用一套人物档案。

本文件是完整的使用说明。前半部分是两个体系通用的内容，后半部分分别介绍印度占星和西方占星自己的功能，最后是给开发者的说明。

## 开始使用

- 安装依赖：`pip install -r requirements.txt`。其中 `sqlcipher3-wheels` 只在需要档案库加密时才用到，不装也能使用其他全部功能。
- 启动：在命令行进入项目文件夹，运行 `python app.py`，然后用浏览器打开 `http://127.0.0.1:5300/`。用 WinPython 时，先打开 WinPython Command Prompt，再用 `cd /d 项目文件夹` 进入项目文件夹。
- 退出：在命令行窗口按 `Ctrl + C`。
- 顶栏最左边的下拉菜单切换「印占」和「西占」。两个体系的计算设置分开保存，人物档案是同一套。
- 改了时间、地点或设置之后，点右上角「排盘」重新计算。星体配置、古典设置等浮窗里点「完成」后会自动重算。
- 设置抽屉里的各个设置一改就自动保存，下次打开程序沿用。

## 页面布局

- 左边是星盘，右边是结果标签页。星盘大小跟着窗口高度走，剩下的宽度都给右边。窗口很窄时上下排列。
- 顶栏只有一行，从左到右：体系、档案库、当前人物、时间条，右端是三盘按钮（只在印占出现）、「排盘」和设置按钮（齿轮）。
  - 体系和档案库都是下拉菜单，点一下打开，点外面或按 Esc 收起。
  - 点人名打开「选择人物」，档案的选择、编辑、新建、删除都在这里（见「人物档案」）。
  - 时间条：本地日期时间、时间步进，看过境盘时还有 ↻（更新到现在）。时间条里的时间就是当前这张盘的时刻，本命和过境各自一份。顶栏的按钮不带鼠标悬停提示。
- 设置抽屉从右边滑出，里面只有时间与地点、计算设置和工具。点抽屉外面、按 Esc 或再点齿轮收起。
  - 「时间与地点」里也有一份本地日期时间，和顶栏的时间条是同一个时刻，在哪一边改都可以，另一边立刻跟着变。
- 星盘上方只有一行：切换星盘，右端是体系自己的控件（印度占星：转宫、北 / 南）。
- 结果表里宫位只写数字（1 到 12），不写「第 N 宫」。
- 结果表横向放不下时，第一列（名称）固定在左边，其余各列在它后面横向滚动，对照不会错行。
- 黄经一列里，星座（符号或三字母缩写）占固定宽度，度数紧跟其后：同一列上下行星座对星座、度数对度数，各自左对齐。西占的三分主星一列同样每颗星占固定的位置，缺的那一位留空。

### 三盘视角（印占）

- 点顶栏「排盘」左边的三盘按钮切换。大星盘不动，右边多出一栏，一上一下两个小星盘，结果标签页排在最右。再点一次回到原来的版面。开关和两个小星盘的选择只在这台电脑的浏览器里记住。
- 这一栏顶上是两个下拉框，分别选上、下两个小星盘：Transit、Moon、Bhava 和全部 D 盘（Rashi、Gochara 除外）。
- 顶栏的时间只跟大星盘走：大星盘是 Rashi（或分盘）时，时间条是本命的时刻；大星盘是 Transit 或 Gochara 时，是过境的时刻。小星盘选了 Transit 时，它用过境盘自己保存的时刻（第一次用时是现在的时间和默认地点），不改动顶栏。
- 大星盘一栏（连同星盘上方那一行按钮）与单盘时完全一样，只是右边的结果区变窄，让出中间一栏。
- 小星盘只画代号、不画度数，代号放大到大星盘的 1.7 倍、星座数字放大到 1.6 倍（挤的格子照样自动缩小）。
- 每张星盘各自记住自己的点击高亮，互不影响。转宫按盘记：大星盘转过的 D9，小星盘里的 D9 也是转过的。
- 窗口很窄时三栏改为上下排列。

## 本命盘与过境盘

- 星盘上方切换本命盘和过境盘。印度占星里这两个按钮叫「Rashi」和「Transit」，西方占星里叫「本命」和「过境」。
- 本命盘用人物档案里的出生资料。先点顶栏的人名选一个人。
- 过境盘是另起的一张盘，默认是现在的时间和你所在的地点。时间条右边的 ↻ 是「更新到现在」。
- 看过境盘时，设置抽屉「时间与地点」里「经纬度」右边多两个小图标：定位（重新取你所在的地点）、改用当前人物的出生地点。旁边的小字写着地点的来源。
- 想把过境这张盘存成一个人物，在「选择人物」里点「新建档案」，它用的就是当前这张盘的时间地点。
- 两张盘各自保存时间地点，来回切换不会互相覆盖。

## 时间与地点

### 输入时间

- 时间条在顶栏，一直显示（设置抽屉里也有一份，两边同步）。年、月、日、时、分、秒各一个小格。点进去直接输入数字，填满一格自动跳到下一格。
- 秒可以带最多 3 位小数，例如 `05.25`。粘贴进来的时间如果小数更多，会四舍五入到 3 位。档案里保存的出生时间同样保留 3 位小数。
- 可以把 `1990-05-12 08:30:00` 这样的整段文字粘贴进任意一格。
- 按上下方向键加减当前这一格。日期不存在时格子变红并提示原因。按回车直接排盘。

### 时间步进

- 选好步长，点 ＋ 往后、点 − 往前，每点一下立刻重新排盘。步长从 1 年到 1 分钟。
- 「4 分钟」大约让上升点移动 1°，适合逐度检查上升点和宫头。
- 步进前后的偏移显示在步进按钮旁边，点它回到起点。
- 步进只改时间条里的时间，不会写进档案。要保存，打开「编辑档案」点「保存」。

### 日出判定基准

两个体系各自保存：印占在计算设置「历法」一组的「日出」，西占在「古典」一组的「日出」，都是点开浮窗修改。日出日落、次日日出、值日星、行星时，以及印占里依赖日出的各项（Panchanga 的 Vara、Kala Vela、Rahu Kala、Abhijit、Vishesha Lagna、Upagraha、Shadbala 的 Tribhaga 等）都按这里。

- **判定基准**：太阳上边缘（天文年历的标准）、日心（默认）、太阳下边缘。
- **大气折射**：关掉时按几何地平计算。
- **计入太阳黄纬**：关掉时不计太阳的黄纬。
- 印度传统的 Hindu rising 是「日心、不计折射、不计黄纬」，三项这样设好后，设置里这一项右侧显示 Hindu。
- 默认值与以前版本相同（日心、计折射、计黄纬），升级后日出时刻不变。以前的设置文件里的 `sunrise_rsmi` 会自动换算成新写法。

### 时区、历法、经纬度

- 在设置抽屉的「时间与地点」里。时区写成 `+08:00` 这样的格式。历法可选格里历（Gregorian）或儒略历（Julian）。
- 经纬度可以用度分秒或十进制输入，在经纬度旁边切换。两种写法会自动同步。度分秒的秒最多 3 位小数，十进制度保留 7 位小数，两种写法来回换算不会改变数值。

## 切换占星体系

- 顶栏的体系切换是即时的。打开过的体系一直保留在内存里，切换时不重新加载页面、不重新排盘，各自的星盘、标签页、滚动位置都保持原样。
- 打开程序后，浏览器空闲时会在后台预先加载另一个体系，所以第一次切换也是即时的。同时保留的体系最多 3 个。以后体系更多时，最久没用的会被释放，再切回去时重新加载。
- 在一个体系里换了人、修改或删除了档案，切到另一个体系时它会自动换成同一个人，用新的资料重新排盘。换了档案库、改了加密、字段或标签时，另一个体系切过去时会重新加载一次。
- 浏览器地址是 `http://127.0.0.1:5300/`。以前的 `/vedic/`、`/western/` 书签仍然可用，会自动转到这里。在体系菜单里按住 Ctrl 点一项，会在新标签页里单独打开。

## 人物档案

### 档案库

- 点顶栏的档案库按钮打开菜单，可以切换、新建、重命名、删除档案库，或设置加密。
- 每个档案库是一套独立的人物、字段和标签，互不相干。
- 「删除档案库…」：选好要删的库，再输入一次它的名称确认。锁定的加密库也可以删，不需要密码。删除的文件不会马上消失，而是移到 `user_data/deleted_libraries/`，文件名后面加上删除时间。想找回时，关掉程序，把文件移回 `user_data/libraries/`，去掉名字里「__已删除-时间」这一段即可。确认不要了，再手动清空这个文件夹。

### 选择人物

- 点顶栏的人名打开列表，点一行即选中并排盘。
- 搜索框左边可选「名字」或「全文」。全文会在名字、标签和所有字段内容里查找，并显示命中的位置。
- 搜索框下面是「排序」：最近打开（默认）、名字、出生时间、最近修改、最近添加，以及每个数字或日期类型的字段。换排序依据时，方向会自动换成它常用的方向（时间类默认近的在前，名字默认正序），也可以再改。
- 排序每个档案库单独记住，关掉网页、重启程序后照样用。按最近打开、最近修改、最近添加或某个字段排序时，每行右侧会显示对应的时间或字段值。
- 「最近打开」指最近一次在列表里选中、或新建后用作本命盘的时间。打开网页时自动选回上次的人不算，切换占星体系也不算。只看盘、不改档案也会更新它。「最近修改」只在保存档案时更新。
- 鼠标移到列表中某一行时，右边会出现编辑（铅笔）和删除两个按钮。编辑打开这份档案的编辑浮窗，不必先选中它；删除确认后直接删掉，不可恢复。
- 「筛选」可以按出生日期范围、标签、字段条件筛选。筛选和搜索不会被记住。「重置筛选」只清空筛选和搜索，排序不变。
- 列表底部可以导出或导入 CSV，右边是「新建档案」。导入时任何一行有错，整个导入都不生效。

### 编辑与新建

- 编辑和新建都从「选择人物」进入。从列表打开的编辑浮窗左上角有返回按钮，点它、点「取消」或按 Esc 都回到列表原来那一页。
- **新建档案**：出生资料就是当前这张盘的时间地点。看本命盘时是本命盘，看过境盘（或 Gochara）时是过境盘。保存后新档案立即用作本命盘。
- **编辑档案**：名称、标签、自定义字段在浮窗里改。编辑当前人物、并且正在看本命盘时，出生资料取自时间条和「时间与地点」，所以步进或改过的时间会一起保存；其它情况出生资料保持档案原样，不会被过境盘的时间覆盖。
- 「保存」覆盖这份档案，「删除」不可恢复。按 Ctrl + 回车也可以保存。

### 档案资料

选中人物后，结果区会出现「档案资料」标签页，显示这个人已填写的全部字段。

## 自定义字段

- 在「编辑档案」浮窗底部的「管理自定义字段」里增加、改名、改类型、删除字段。
- 字段类型：
  - 文本：可写长篇内容，最多 20000 字。
  - 数字、日期：可以按大小排序和按范围筛选。日期可写 `2020-05-12`、`2020-05` 或 `2020`。
  - 单选、多选：先定义好选项，可以按选项筛选。
  - 分组：自己不存内容，只用来收纳下级字段。
- 字段可以嵌套，最多 5 层。例如在分组「婚姻」下面放「婚姻状况」「结婚次数」「婚姻详情」。新建时在「上级」里选放在哪里；已有的字段改自己那一行的「上级」即可移动。
- 同一级里字段名不能重复，字段名里不能有「/」。排序、筛选和 CSV 里写完整路径，如 `婚姻/结婚次数`。
- 删除字段会同时删除所有档案里这一项的内容，连同它的下级字段，不可恢复。

## 档案库加密

- 加密按档案库分别设置，每个加密的库有自己的密码。入口在档案库菜单的「加密当前档案库…」。已加密时，这一项显示为「加密设置（取消加密 / 改密码）…」。
- 在这里可以加密、取消加密、立即锁定、更改密码，都只作用于当前档案库。
- 打开程序或切换到锁定的库时，会先弹出密码窗口。输入密码解锁，也可以在窗口里改用其他档案库。
- **不想每次输密码**：解锁后打开档案库菜单的「加密设置（取消加密 / 改密码）…」，输入当前密码，点「取消加密」。这个库就变回普通档案库，以后打开不再需要密码。取消加密不会改动任何档案内容。
- 加密的库在菜单里有一个锁形图标。
- 加密使用 SQLCipher（AES-256）。加密后速度与未加密时基本相同。
- **密码不保存在任何地方。忘记密码，这个档案库无法找回。** 请定期备份。
- 需要先安装 `sqlcipher3-wheels`（`pip install sqlcipher3-wheels`）。没装时其他功能照常。
- 导出的 CSV 是明文，请自行保管。

## 工具

在「计算设置」最下面的「工具」里。

- **结果标签页顺序**：调整星盘下方标签页的先后，点「完成」生效。两个体系各记一份。
- **原始参数**：查看当前这张盘后端返回的全部原始数值（不四舍五入），用来核对计算结果。可以一键复制 JSON。
- **导入 / 导出设置**：点开后选择要做哪一件事。
  - 导出：把两个体系的全部设置存成一个 JSON 文件。不含档案数据，也不含服务器地址。
  - 导入：选择导出的文件，替换当前设置，页面随后重新载入。别的项目组导入这个文件，就能用完全相同的设置起盘。

## 印度占星

### 计算设置

黄道、岁差、宫位制、月交点四项在最上面直接改。其余和西占一样分组列出（体系：KP、分盘、Dasha、Yoga；星盘：相位、特殊点；行星：尊贵、燃烧、行星状态；表格：力量、八重点、敌友、分盘汇总；历法：日出、年月 · 吉时），每一项右边是当前设置的摘要，点开在浮窗里修改。浮窗里的修改点「完成」才保存并重算，「取消」或 Esc 放弃，「恢复默认」把这一项填回默认值（同样点「完成」才生效）。

- **黄道体系**：恒星黄道（Sidereal）或回归黄道（Tropical）。星盘、KP、Dasha、分盘都在所选黄道的黄经上计算。
- **岁差体系**：只在恒星黄道下使用。KP 通常用 Krishnamurti，传统 Parashari 常用 Lahiri。
- **宫位制**、**月交点**（平交点或真交点）。
- **KP**：勾选「启用 KP」后计算 KP 行星、KP 宫位、KP 行星 ABCD、KP 宫位 1234 和 KP 主宰星，对应的标签页一起出现。KP 卜卦也在这一栏，KS-N 签号 1 到 249，CIL-N 签号 1 到 2193。卜卦只在启用 KP 时起作用。
- **分盘**：见下面的「分盘」一节。
- **相位**：罗睺、计都是否投射第 5、7、9 个星座的相位，两项分开设置，默认都投射。星盘的点击高亮、Gochara 和 Yoga 里的相位都按这里计算。
  - **Jaimini 星座互看**：开启后，星盘上的行星不能再点；点星座数字，这个格子和与它互看的星座格子高亮（动星座看定星座、定星座看动星座，相邻的除外；变星座互看）。Yoga 的相位不受这一项影响。
- **尊贵**：七曜的极旺度数（擢升星座内的度数，默认 BPHS：Su 10、Mo 3、Ma 28、Me 15、Ju 5、Ve 27、Sa 20），极旺、极落的容许度（默认 1°），罗计的旺座（金牛 · 天蝎，或双子 · 射手；Yoga 的 `exalted` 等也按这里），不在庙、旺、落时是否标出与星座主星的五重敌友关系（默认标出）。「恢复默认」改回 BPHS。
- **行星状态**：Chara Karaka 用 8 个（含罗睺）还是 7 个；四种特殊度数各自开关（死度、吉度、吉分、甘丹塔），死度的出处（Phaladeepika 或 Jataka Parijata，两者只有月亮一行不同），度数范围（第 n 度即 n−1° 到 n°，或 n° 前后 0.5°），甘丹塔的宽度（默认 3°20′）；行星战的开关、相距度数（默认 1°）和胜负规则（黄纬偏北者胜、赤纬偏北者胜、较亮者胜）。
- **特殊点**：哪些 Vishesha Lagna、Upagraha、Arudha 画进星盘（默认都不画）；BL、HL、GL、Vighati 的起点（日出时的太阳，或出生时的太阳）；Gulika、Mandi、其余 Kala Vela 各取那一段的起点、中点还是终点（默认 Gulika 起点、Mandi 中点、其余起点）；天蝎、水瓶的主星（两主星取较强者，或只用火星、土星）；Arudha 落在本宫或第 7 宫时是否改取第 10 宫。
- **力量 · 八重点 · 敌友 · 分盘汇总**：Shadbala 里水星的吉凶（与凶星同宫为凶，或始终为吉）；八重点的列序（按星座，或从 Lagna 起）；罗计是否列入敌友表和分盘计分；Vimsopaka、Vaiseshikamsa 各用哪一组分盘（Shadvarga、Saptavarga、Dashavarga、Shodashavarga，默认分别是 Shodashavarga、Dashavarga）。
- **历法**：太阴月按 Amanta（新月起）还是 Purnimanta（满月起）；六十年按南印太阴年还是北印木星年；南北行按恒星（Makara Sankranti 起）还是回归（冬至起）；周三是否不取 Abhijit。
- 行星战、力量、特殊点的时点、历法由后端计算，改了以后按原来的时刻重新排盘；其余各项只在页面上计算，改了立即重画。
- **燃烧**：行星离太阳多少度以内算燃烧（Combust）。默认按 BPHS：月 12°、火 17°、水 14°、木 11°、金 10°、土 15°。BPHS 对逆行的水星、金星另给了较小的度数（12°、8°），所以设置里多出「Me 逆行时」「Ve 逆行时」两格：行星表判断燃烧时，水星、金星正在逆行就用这两格，顺行用前面的度数。行星表的「燃烧」一栏和 Yoga 里的 `combust(P)` 都按这里，「恢复默认」改回上面的度数。
- **Yoga**：「管理 Yoga」在这里，见下面的「Yoga」一节。
- **Dasha**：见下面的「Dasha」一节。

### 星盘

- 星盘右上角的「北 / 南」切换北印度和南印度样式。
- 星盘上方的「转宫」：选一个星座的编号（1 是白羊，12 是双鱼），星盘就以这个星座为第一宫。北印度盘整个旋转，南印度盘的斜线移到这个星座，Asc 仍然画在它真正所在的星座里。转过宫时下拉框有红框。
  - 除 Moon 以外的每张盘（Rashi、Transit、Bhava、各个 D 盘、Gochara）各自记自己的转宫，互不影响；Gochara 与 Rashi 共用一个（里面那张就是 Rashi）。
  - 转宫只改变星盘，结果表和 Yoga 不变。
  - 转宫是看盘时的临时操作，只在这一页里记住，换人或重新打开程序后回到 Lagna。
- 每个格子代表一个星座，度数是星座内度数。北印度盘最上方的菱形是上升星座。南印度盘星座位置固定，上升星座的格子左上角有一道斜线。
- 行星用两字母代码：Su 太阳、Mo 月亮、Me 水星、Ve 金星、Ma 火星、Ju 木星、Sa 土星、Ra 罗睺、Ke 计都。代码下有红线表示逆行。
- Asc 是上升点。非整宫制下，H1 到 H12 是各宫宫头，连同度数放进它所在的星座。H1 与上升点相同时只画 H1，不同时（如 Equal/MC 宫制）另外画出 Asc。
- 计算设置「特殊点」里勾选的点（Vishesha Lagna、Upagraha、Arudha）用灰紫色画进星盘，不能点。只有星座、没有度数的点（Indu Lagna、各个 Arudha）只写代号。分盘里，Vishesha Lagna 和 Upagraha 按分盘算法换算，Arudha 按这张分盘里各行星的位置重新计算；Bhava 盘里按宫头放进宫位格子。
- 点一颗行星，高亮它投射相位的星座；点星座数字，高亮向这个星座投射相位的行星（开启 Jaimini 星座互看时改为高亮互看的星座）。相位按 Parashari 星座相位计算：所有行星看第 7 个星座，火星另看第 4、8 个，木星另看第 5、9 个，土星另看第 3、10 个；罗睺、计都默认另看第 5、9 个，可以在计算设置的「相位」里关掉。

### 分盘

星盘上方是常用的几张盘：**Rashi**（本命）、**Transit**（过境）、**Moon**、**Bhava**、**Gochara**，最后是**分盘按钮**。

- 分盘按钮分左右两半。左半边写着一张分盘的编号（默认 D9），点它直接切到这张分盘；右半边 ▾ 打开全部 16 张 BPHS 分盘的菜单，每张写着编号、梵文名和主要看什么。
- 在菜单里选过的分盘会成为左半边的新默认，下次点左半边就直接到这张（只在这台电脑的浏览器里记住）。
- 菜单浮在页面最上层，总是完整显示在窗口以内，不会被星盘一栏截断。

- 分盘只在点到时才计算，算好后保留，直到本命盘重新计算，或这张分盘的设置改了。分盘再多也不会拖慢页面。
- 分盘只改变星盘。下方的结果表始终是本命盘的数据，切到 Transit 时才换成过境盘的数据。Yoga 标签页例外，它跟着星盘走（见下面的「Yoga」一节）。
- **Moon**：行星位置不变，以月亮所在星座为第一宫。
- **D 盘**：每个点（行星、罗睺、计都、上升点）按所选算法换算到分盘里。格内度数是它在这一份里走过的进度（换算到 0° 到 30°）。分盘不画宫头。
- **Gochara**：Rashi 盘本身，再把过境的九曜放进同一张盘里。过境行星按它真实所在的星座放进对应的格子，排在同一格本命行星的后面，用鼠尾草绿，本命行星是米白色。过境的上升点不画。
  - 显示 Gochara 时，时间条和设置抽屉里是过境的时间与地点（与 Transit 共用同一个时刻）。改时间、时间步进、「更新到现在」都会立刻重排过境行星。地点不影响过境行星落在哪个星座。右边的结果区仍是 Rashi 的内容。
  - 点本命或过境的行星：它所在的格子和它投射相位的格子高亮。
  - 点星座数字：这个格子高亮，本命和过境里向它投射相位的行星都标出来。
  - 北印度盘、南印度盘都一样。转宫对 Gochara 同样有效（和 Rashi 共用一个）。
- **Bhava**：一个格子就是一个宫位，不再是一个星座。第 n 宫是从第 n 宫宫头到第 n+1 宫宫头的范围；Sripati 宫位制的宫头就是每一宫的起点（Sandhi）。格子的摆法与 Rashi 相同，第 1 宫放在上升星座的位置，格内数字照常是星座数字。点的度数照常是它在真实星座里的度数，宫头度数不画。鼠标停在点上会显示它在第几宫。相位按宫位数。

### 分盘设置

在计算设置「体系」一组的「分盘」浮窗里，点「完成」后生效并保存。转宫不在这里，在星盘上方（见上面的「星盘」一节）。

- **Bhava 宫位制**：Bhava 盘用的宫位制，默认 Sripati，可选的宫位制与上面的「宫位制」相同，两者互不影响。Bhava 宫位制与「宫位制」不同时，点开 Bhava 盘时会另外向后端要一次宫头（KP 卜卦开着时同样按签号定上升点）。
- **分盘算法**：点开后每张分盘一行，选用哪一种算法，下面写着这种算法的规则和出处。只有一种算法的分盘不能选择。浮窗的「恢复默认」把所有分盘改回默认算法。设置里这一项右侧会显示有几张分盘没有用默认算法。

### Yoga

结果区的「Yoga」标签页列出当前这张盘上成立的 Yoga，按分类分组。默认带 123 条，可以停用、修改、删除，也可以自己新建。标签页只看结果；停用、修改、新建都在设置抽屉的「管理 Yoga」里。

#### 算哪张盘

Yoga 跟着星盘走：Rashi 和 Gochara 算本命盘，Transit 算过境盘，Moon 以月亮所在星座为第一宫，Bhava 按宫位（一个格子一个宫），各个 D 盘按当前的分盘算法换算后的位置。标签页顶部写着现在算的是哪张盘。

- 宫位一律按格子数：一般的盘是整宫制（星座就是宫位），Bhava 盘按 Bhava 宫位。计算设置里的「宫位制」不影响 Yoga。
- 入庙、擢升等尊贵按点真实所在的星座判断。逆行、燃烧、日生夜生、月亮上弦下弦按本命盘（Transit 时按过境盘）的真实位置判断，在分盘里也一样。
- 相位按计算设置里的「相位」（罗睺、计都是否投射相位）。
- 只在 Yoga 标签页正显示时才计算。同一张盘、同一套设置只算一次，换盘或改设置后才重算。

- 每条显示名称、中文名、主要含义和条件说明。鼠标停在一条上会显示出处和公式。

- 有公式写错的 Yoga 时，顶部会出现「N 条公式有错」，点它打开「管理 Yoga」检查；写错的那条不影响别的。

#### 管理 Yoga

在设置抽屉「计算设置」里点「管理 Yoga」（右边的数字是启用 / 全部）。

- 勾选框启用或停用一条 Yoga。可以按名称、说明、公式搜索，或按分类筛选。
- 点一行的任何地方（勾选框、删除除外）进入编辑。编辑时标题左边的 ‹、下方的「返回列表」、Esc 都回到列表；在列表里按 Esc 才关闭浮窗。
- 删除（垃圾桶）：自定义的 Yoga 删除后不能恢复；默认的 Yoga 删掉后可以用「恢复全部默认」找回。
- 编辑或「新建 Yoga」：填写名称、中文名、分类、条件公式、条件说明、主要含义、出处。写公式时下面会立即提示写法对不对，以及在当前这张盘上成立与否。
- 改过的默认 Yoga 标着「已修改」，编辑时可以「恢复成默认写法」。
- 「恢复全部默认」：删掉的默认 Yoga 回来，改过的默认 Yoga 改回原样，所有默认 Yoga 重新启用。自定义的 Yoga 不受影响。
- 所有改动立即保存在 `settings.json`，会随「导入 / 导出设置」一起导出导入。

#### 公式写法

一条 Yoga 就是一个判断成立或不成立的公式，例如：

```
house(Ju, Mo) in KENDRA                      木星在月亮起的角宫（Gaja Kesari）
assoc(lord(9), lord(10))                     第 9、10 宫主有关联
debilitated(Sa) and house(Sa) in KENDRA      土星入弱并在角宫
all_in(P7, run(1, 7))                        七曜全在第 1 到第 7 宫（Nauka）
```

- 行星写代号：`Su Mo Ma Me Ju Ve Sa Ra Ke`。`Asc` 是上升点，`Lagna` 是这张盘的第一宫（Moon 盘就是月亮所在的星座）。
- 宫位从 1 数起；星座 1 是白羊，12 是双鱼。列表写成 `[1, 4, 7, 10]`。
- 运算：`and`、`or`、`not`（也可以写「且」「或」「非」）；`==`、`!=`、`<`、`<=`、`>`、`>=`；`in`、`not in`（在不在列表里）；`+`、`-`（数字加减，列表合并或去掉某几项）；括号。中文的全角括号和逗号也可以用。
- 常数：`KENDRA`（1、4、7、10）、`TRIKONA`（1、5、9）、`DUSTHANA`（6、8、12）、`UPACHAYA`（3、6、10、11）、`PANAPHARA`、`APOKLIMA`、`MOVABLE` / `FIXED` / `DUAL`（动定变星座）、`P9`（九曜）、`P7`（七曜）、`P5`（火水木金土）、`NB` / `NM`（天然吉星、凶星的固定写法）。
- 函数分几类（完整的写法和说明在编辑窗口的「公式写法」里，从程序里直接生成，始终和实际支持的一致）：
  - 位置：`house(P[, 从])`、`sign(P)`、`deg(P)`、`lon(P)`、`in_house(n[, 从])`、`houses_of(列表[, 从])`、`all_in` / `any_in` / `count_in(列表, 宫位[, 从])`、`all_in_signs(列表, 星座)`、`signs_occupied(列表)`、`run(起, 个数)`、`all_between(列表, A, B)`
  - 宫主：`lord(n[, 从])`、`lords_of(P)`、`signlord(P)`、`exlord(P)`、`deblord(P)`、`yogakaraka(P)`、`parivartana(宫位列表, 宫位列表)`
  - 关系：`conj(A, B, ...)`、`aspect(A, B)`、`aspect_house(A, n)`、`aspected_by(P)`、`exchange(A, B)`、`assoc(A, B)`、`friend(A, B)`、`enemy(A, B)`
  - 尊贵与状态：`own(P)`、`exalted(P)`、`debilitated(P)`、`mt(P)`、`strong(P)`、`exsign(P)`、`friend_sign(P)`、`enemy_sign(P)`、`retro(P)`、`combust(P)`、`benefic(P)`、`malefic(P)`、`benefics()`、`malefics()`、`waxing()`、`day()`
  - 分盘：`dsign(P, n)`（P 在 Dn 的星座，按当前的分盘算法）
  - 列表：`count`、`unique`、`inter`、`subset`

#### 性能

公式在第一次用到时编译成普通的 JavaScript 函数（全部默认 Yoga 一共几毫秒，而且是在浏览器空闲时提前做好），之后每张盘只是查表和比较。实测一张盘算完全部默认 Yoga 约 0.15 毫秒；同样的规则直接手写成程序约快 3 倍，也就是省下不到 0.1 毫秒。低端电脑按慢 10 倍估计，一张盘也在 2 毫秒左右，远低于一帧（16 毫秒），所以默认 Yoga 和自定义 Yoga 共用这一套引擎。

- 双盘：内圈是完整的本命盘（星座、宫位、恒星、盘中元素），外圈是这张盘的行星、小行星、特殊点、Lot，以及它的上升（Asc）和中天（Mc）。外圈各点在第 1 圈外侧有真实位置的刻度，子项顺序与内圈对称（符号离星座圈最近）。
- 双盘时点一个元素（内圈或外圈都可以），高亮与它构成双盘相位的元素。鼠标停在元素上，显示它的双盘相位。
- 双盘时结果区上方多一条「外圈的盘 / 本命」切换，决定行星、宫位、相位、恒星等标签页显示哪张盘的数据。
- 相位标签页多一个「双盘相位」视图（打开双盘时默认显示它）：上方是矩阵，每行是外圈的点，每列是内圈的点；下方是全部双盘相位按偏差从小到大的列表。入相、出相按外圈那张盘的运动判断（本命不动）。
- 参与双盘相位的点与「相位 → 行星选用」相同。容许度在「相位 → 双盘容许度」里，每张盘单独设：统一度数（默认过境 2°，次限、三限、日弧 1°），或「相位设置 × 系数」（默认日返、月返 × 1，即与本命相位相同的容许度）。外圈、内圈的四轴是否参与，也在这里勾选。

**日返 / 月返**

- 太阳（月亮）回到「本命位置 + 指定度数」的时刻起盘。度数填 0 是返照，180 是半返，90、270 是四分返，也可以填任意度数。
- 黄道：跟随计算设置，或固定用回归黄道 / 恒星黄道。恒星黄道就是含岁差修正的返照，岁差体系用计算设置里的那一种。
- 选哪一次：顶栏时间之前最近一次（当前生效的返照）、之后第一次、离得最近的一次。「再往后数」可以再往后或往前跳几次。
- 起盘地点：出生地、顶栏地点（即迁移返照），或自定义经纬度和时区。宫位制可以单独指定。
- 精度：返照时刻用牛顿法求到黄经误差 0.00001″ 以内。

**次限 / 三限**

- 推运时刻 = 出生时刻 + (目标时刻 − 出生时刻) × 星历日数 / 人生日数。次限默认「1 日 = 1 回归年（365.24219 日）」，三限默认「1 日 = 1 回归月（27.321582 日）」。两个数字都可以随意改，例如把三限改成「27.321582 日 = 365.24219 日」就是小限推运（Minor）。逆推时往出生之前推。
- 行星取推运时刻的真实位置。中天有六种推法：太阳弧（黄经）、太阳弧（赤经）、固定速率（黄经 / 赤经，默认 Naibod 0.98564733°，可改成 1° 或任意数）、推运时刻的真实恒星时、保持本命。上升和宫头由推出的中天在「宫位地点」的纬度上算出，宫位制可以单独指定。
- 实现上中天只由 ARMC（中天的赤经）决定，推出的 ARMC 与目标的误差在 0.01″ 以内。

**日弧**

- 本命盘所有的点一律加上同一段弧。弧的来源：次限太阳走过的黄经弧、赤经弧（次限的速率可改），或固定速率 × 年数。
- 弧加在黄经上，或加在赤经上（把点换算到赤经、加弧、再换回黄道上同一赤经的点）。
- 宫头：一起加弧、由加弧后的中天在所选地点重算，或保持本命。恒星默认不加弧，可以勾选。映点与反映点按加弧后的行星重新计算。

**小限**

- 起点默认上升，也可以是中天、七颗古典行星或任何一个 Lot。跳法：整星座（每年跳一个星座）、按度数（每年 30°，从起点的度数起）、连续移动（按时间比例平滑移动）。
- 年的起点：每年太阳回归的时刻（默认）、生日（日历周年；2 月 29 日出生的平年取 2 月 28 日），或出生时刻 + 固定年长。每年前进几个星座可以改（负数倒走）。
- 月：把一年等分成 N 份（默认 12，可以填 13 或任意数）、固定天数，或太阳每走一段度数（默认 30°）。月小限默认从当年的年小限起，也可以从本命起点起。日：把一个月等分（默认 12 份，约 2.5 日），或固定天数。
- 星座主星：古典七星，或现代（天蝎冥王、水瓶天王、双鱼海王）。
- 星盘外面三圈从里往外是年、月、日。每圈 12 格就是 12 个星座（与盘面的星座对齐），格子里是这个星座的主星，当前的那一格高亮；按度数或连续移动时，格子里还有一条白线标出准确的度数。鼠标停在格子上看说明。
- 「小限」标签页：当前的年、月、日小限（星座、主星、全星座宫位、本命落在这个星座的星体、起止时间），本年各月、本月各段，以及年表。

**法达**

- 日生 / 夜生按本命盘（用「古典 → 得时」里的日夜判断），也可以固定按日生或夜生。
- 主限顺序可以直接改（填行星代码 Su Mo Me Ve Ma Ju Sa Ra Ke，用空格分开）。夜生默认 Abu Ma'shar 的顺序（交点紧跟火星），一键可换成 Bonatti 的顺序（交点放在最后）。每颗星的年数也都可以改，一轮的总年数自动跟着变，过了一轮从头再来。
- 子限：七等分，或按各星年数的比例。顺序默认从主限星起按迦勒底序（土、木、火、日、金、水、月），也可以按主限顺序。交点默认不分子限；勾选后交点也分子限（迦勒底序时从土星起）。
- 年长：默认出生时刻 + 固定年长（回归年），也可以按每年的太阳回归或生日。
- 星盘外面两圈：里圈是当前主限的子限，外圈是一整轮主限。一圈从上升一侧（正左）开始沿逆时针走，按年数分格，白线是现在的位置，走过的格子变淡。
- 「法达」标签页：一整轮的主限和子限，起止时间、起始年龄、年数，当前的主限和子限高亮。

## 文件与备份

- 所有用户数据都在 `user_data` 文件夹里。备份时先关闭程序，再复制整个文件夹。
- `user_data/libraries/`：每个档案库一个 `名字.sqlite3` 文件。程序运行时旁边会有 `-wal` 和 `-shm` 两个文件，属正常现象，不要单独删除。
- `user_data/deleted_libraries/`：删除的档案库放在这里，可以找回。
- `user_data/settings.json`：全部设置。网页上的改动会自动写入；手工修改后需要重启程序。`server` 一节可以改端口。
- 档案库为几十万份档案设计。20 万份档案时，翻页、排序、打开和保存一份档案都在 5 毫秒以内，筛选和全文检索一般在 0.1 到 0.3 秒。
- 星历使用 Swiss Ephemeris 的星历文件，放在 `common/astro/ephe`。缺少某个文件时，结果表下方会写明缺哪一个。

### 目录

```
app.py              启动入口

user_data/          设置和档案库（不属于代码，备份时连同它一起备份）
```

- `systems/` 下的体系是自动发现的。删掉某个体系的文件夹，程序照常运行，只是少了那个体系。

### 星盘视图与分盘基底（common/static/common.js）

体系的前端用 `registerSystem({...})` 挂进共用页面。和星盘视图有关的挂接点：

- `viewLabels`：改写本命、过境两个按钮的名称（印度占星改成 Rashi、Transit）。
- `derivedViews`：从本命盘换算出来的分盘，`{键: {label, derive, signature, bar, order, form}}`。
  - `derive(本命结果, {payload, transit})` 只在点到这张盘时才调用。可以直接返回结果，也可以返回 Promise（需要向后端要数据时，例如 Bhava 盘）。返回 Promise 时先显示「计算中…」。
  - `signature()` 返回这张分盘自己的设置（如算法名）。它变了，缓存就失效，下次显示时重新换算。
  - `bar: false` 表示不放在按钮条上，只出现在下拉菜单里。`order` 决定按钮条上的先后（印度占星在 `vedic.js` 的 `BAR_ORDER` 里改）。
  - `form: "transit"` 表示时间条、设置抽屉里的时间地点和「排盘」用过境盘，`derive` 另外收到过境结果（Gochara 用）。这时右边的结果区仍显示本命盘。
  - `ownResults: true` 表示右边的结果区显示这张分盘自己算出的结果（西方占星的日返、次限等）。分盘没算好时结果区暂时为空。
- `adjustResults(结果, 视图)`：最后再改写一次结果区用哪张盘的数据（西方占星的双盘「外圈 / 本命」切换用它）。
- `renderSunTab(容器, 结果)`、`tabLabels`：换掉「值日星 · 行星时」标签页的内容和名称（印度占星换成「历法」）。
- `onProfileChange(人物)`：换了人（印度占星用它清掉转宫）。
- `defaultTabOrder`、`tabOrderRev`：结果区标签页的默认顺序。改了默认顺序时把 `tabOrderRev` 加 1，之前在「工具」里保存的顺序（`settings.json` 的 `layout.tab_order_rev` 记着保存时的版本号）就不再使用，回到新的默认顺序。
- `onDerivedReady(视图)`：一张要等后端的分盘刚算好、已经重画（印度占星用它在 Bhava 盘算好后刷新 Yoga）。
- `systems/vedic/static/vedic_settings.js`：印占计算设置的浮窗（内容是 `index.html` 里的 `<template id="vdlg-类别">`，控件用 `data-set="根.路径"` 对应设置）。
- `miniViews`、`miniDefaults`：三盘视角的两个小星盘可选哪些盘（`[{value, label}]`，视图键可以是 `transit` 或 `derivedViews` 里的任何一张）和默认选哪两张。体系不提供时没有三盘按钮。`renderChart` 画小星盘时第三个参数里带 `mini: true`。
- `viewMenu`：按钮条右边的分盘按钮，`{label, defaultValue, items: [{value, label, note, sub, title}]}`。左半边切到最近用过的那张（没用过时是 `defaultValue`），右半边打开菜单。分盘再多，页面上也只多一个按钮。

换算结果按「本命结果 + signature」缓存在 `state.derived`，没点到的分盘永远不计算，所以分盘数量不影响页面速度。

### 怎样加一张分盘，或给分盘加一种算法

分盘的规则全部登记在 `systems/vedic/static/vargas.js`，菜单、算法浮窗、星盘说明都从这里自动生成，不需要改别的文件。

- 加一种算法：在那张分盘的 `methods` 里加一项 `{label, source, note, toLon}`。`toLon(黄经)` 返回分盘黄经（0° 到 360°）。文件里有现成的工具函数：`equalParts`（等分，连续往后数）、`mappedParts`（等分，每份直接指定星座）、`unequalParts`（不等分）、`cyclic`（循环法）。算法的键只能用小写字母、数字、`_` 和 `-`，它会写进 `settings.json`。
- 加一张分盘（例如 D5、D81、D108）：在 `VARGAS` 里按同样的格式加一项。
- 也可以在另一个文件里调用 `VedicVargas.addMethod(分盘, 键, 算法)` 或 `VedicVargas.register(分盘)`，这个文件要在 `vargas.js` 之后、`vedic.js` 之前加载。
- 每张分盘的第一种算法是默认算法。设置里保存的算法被删掉时，自动退回默认算法。
- D 盘默认都在分盘按钮里。想把某张 D 盘单独放到按钮条上，改 `systems/vedic/static/vedic.js` 里的 `PINNED_VARGAS`（顺序在 `BAR_ORDER`）；分盘按钮左半边的默认盘是 `buildViewMenu()` 里的 `defaultValue`。

### 印度占星的接口（/vedic/api/）

- `POST /chart/full`：排盘。
- `POST /bhava`：Bhava 盘的宫头。请求与 `/chart/full` 相同，另加 `house_system`。
- `POST /varga`：保存分盘设置（`rashi_lagna`、`bhava_house_system`、`methods`）。
- `POST /aspects`：保存相位设置（`{"Ra": true, "Ke": false}`）。
- `POST /combust`：保存燃烧度数（`{"Mo": 12, "Me_r": 12, ...}`，0 到 30）。
- `POST /yogas`：保存 Yoga 设置（`disabled`、`removed`、`custom`，传来的几项整项替换）。后端只检查格式，公式由页面上的引擎检查。
- `POST /jyotish`：保存尊贵、状态、特殊点、力量、八重点、敌友、分盘汇总、历法的设置（`{节: {项: 值}}`，只改传来的几项）。
- `POST /calc-defaults`（含 `sunrise`）、`POST /chart-style`、`POST /dasha/expand`。

分盘设置保存在 `settings.json` 的 `systems.vedic.varga`：

```json
"varga": {
  "rashi_lagna": "asc",
  "bhava_house_system": "Sripati",
  "methods": {"D2": "parivritti"}
}
```

`rashi_lagna` 是 `"asc"`（跟随上升点）或 0 到 11（白羊到双鱼）；`methods` 里只写没有用默认算法的分盘。

相位和 Yoga 设置保存在 `systems.vedic.aspects` 和 `systems.vedic.yogas`：

```json
"aspects": {"Ra": true, "Ke": true},
"yogas": {
  "disabled": ["bhava.1_1"],
  "removed": ["dosha.shrapit"],
  "custom": [{"id": "u.xxxx", "name": "...", "cn": "", "cat": "custom", "rule": "house(Ju) in KENDRA",
              "desc": "", "effect": "", "src": ""}]
}
```

`custom` 里 `id` 与某条默认 Yoga 相同的，表示改过的默认 Yoga。

尊贵、状态等设置保存在 `systems.vedic.jyotish`，每一项的写法和合法值见 `bridge.py` 的 `JYOTISH_DEFAULTS` 和 `JYOTISH_SPEC`：

### 西方占星的推运盘（systems/western/）

- `predictive_settings.py`：七张推运盘的设置。每个字段的类型、范围、默认值、快捷按钮、显示条件都写在 `SPEC` 里；后端用它校验，网页用它（`/western/api/bootstrap` 的 `options.predictive_spec`）画设置浮窗。加一个设置项只改这一个文件，再在 `predictive.py` 里用上它。设置保存在 `systems.western.predictive`。
- `predictive.py`：全部计算。返照时刻用牛顿法求解；次限、三限、日弧的宫位由 ARMC 决定：把起盘经度换成「目标 ARMC − 那一刻的格林尼治恒星时」，就能直接复用本命排盘的全部代码。小限、法达的年由 `YearClock` 统一处理（固定年长 / 生日 / 太阳回归）。
- 接口：`POST /western/api/predictive`，`{kind, natal: 本命排盘请求, target: 顶栏时间地点（与 birth 同格式）, settings?}`。`kind` 是 `solar_return`、`lunar_return`、`secondary`、`tertiary`、`solar_arc` 时返回一张完整的盘（与 `/chart/full` 同结构，另有 `predictive.caption`）；是 `timelords` 时返回 `{target, profection, firdaria, errors}`。`POST /western/api/predictive-settings` 保存设置。
- 双盘相位：`POST /western/api/cross-aspects`，`{view, options: {points, aspects}, outer: 外圈的盘, inner: 本命盘}`，盘只需要 `planet_pos`、`house_result.axes`、`asteroids`。返回 `{aspects: [{a: 外圈点（o: 前缀）, b: 内圈点, ...}], outer, inner, orb}`。容许度设置在 `predictive_settings.py` 的 `biwheel` 一节。双盘由 `chart.js` 的 `render(容器, 本命, {outer, cross, caption})` 画出。
- 前端在 `static/predictive.js`（要在 `western.js` 之前加载）。星盘外面加的几圈由 `chart.js` 画，数据写在结果的 `outer_rings` 里（格式见 `chart.js` 开头的说明），以后别的盘也可以用。
