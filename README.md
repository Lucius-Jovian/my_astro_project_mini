# Quant Astro

本地运行的排盘程序，包含印度占星（Vedic / KP）和西方占星两个体系，两个体系共用一套人物档案。

本文件是完整的使用说明。前半部分是两个体系通用的内容，后半部分分别介绍印度占星和西方占星自己的功能，最后是给开发者的说明。

## 开始使用

- 安装依赖：`pip install -r requirements.txt`。其中 `sqlcipher3-wheels` 只在需要档案库加密时才用到，不装也能使用其他全部功能。
- 启动：在命令行进入项目文件夹，运行 `python app.py`，然后用浏览器打开 `http://127.0.0.1:5300/`。用 WinPython 时，先打开 WinPython Command Prompt，再用 `cd /d 项目文件夹` 进入项目文件夹。
- 退出：在命令行窗口按 `Ctrl + C`。
- 页面顶部左边切换「印度占星」和「西方占星」。两个体系的计算设置分开保存，人物档案是同一套。
- 改了时间、地点或设置之后，点右上角「排盘」重新计算。星体配置、古典设置等浮窗里点「完成」后会自动重算。
- 左侧各个设置一改就自动保存，下次打开程序沿用。

## 本命盘与过境盘

- 星盘左上角切换本命盘和过境盘。印度占星里这两个按钮叫「Rashi」和「Transit」，西方占星里叫「本命」和「过境」。
- 本命盘用人物档案里的出生资料。先在左侧「选择人物…」里选一个人。
- 过境盘是另起的一张盘，默认是现在的时间和你所在的地点。左侧过境面板的四个按钮分别是：更新到现在、重新定位、改用当前人物的出生地点、把这张盘存为新档案。
- 两张盘各自保存时间地点，来回切换不会互相覆盖。
- 按 **Tab** 键，右下角的结果区会上移盖住星盘，方便查看较长的表格。再按一次 Tab 归位，按 Esc 也可以归位。结果区右上角的小箭头按钮作用相同。
- 光标在输入框、下拉框里时，Tab 仍然是跳到下一格，不会触发上移。打开浮窗时也不会触发。在同一个浏览器标签页里切换印度占星和西方占星，上移状态会保持。

## 时间与地点

### 输入时间

- 年、月、日、时、分、秒各一个小格。点进去直接输入数字，填满一格自动跳到下一格。
- 秒可以带最多 3 位小数，例如 `05.25`。粘贴进来的时间如果小数更多，会四舍五入到 3 位。档案里保存的出生时间同样保留 3 位小数。
- 可以把 `1990-05-12 08:30:00` 这样的整段文字粘贴进任意一格。
- 按上下方向键加减当前这一格。日期不存在时格子变红并提示原因。按回车直接排盘。

### 时间步进

- 选好步长，点 ＋ 往后、点 − 往前，每点一下立刻重新排盘。步长从 1 年到 1 分钟。
- 「4 分钟」大约让上升点移动 1°，适合逐度检查上升点和宫头。
- 旁边显示相对起点偏移了多少，点「↺ 回到起点」恢复。
- 步进只改左侧表单里的时间，不会写进档案。要保存，打开「编辑档案」点「保存」。

### 时区、历法、经纬度

- 时区写成 `+08:00` 这样的格式。历法可选格里历（Gregorian）或儒略历（Julian）。
- 经纬度可以用度分秒或十进制输入，在经纬度旁边切换。两种写法会自动同步。度分秒的秒最多 3 位小数，十进制度保留 7 位小数，两种写法来回换算不会改变数值。

## 切换占星体系

- 顶部的「印度占星」「西方占星」切换是即时的。打开过的体系一直保留在内存里，切换时不重新加载页面、不重新排盘，各自的星盘、标签页、滚动位置都保持原样。
- 打开程序后，浏览器空闲时会在后台预先加载另一个体系，所以第一次切换也是即时的。同时保留的体系最多 3 个。以后体系更多时，最久没用的会被释放，再切回去时重新加载。
- 在一个体系里换了人、修改或删除了档案，切到另一个体系时它会自动换成同一个人，用新的资料重新排盘。换了档案库、改了加密、字段或标签时，另一个体系切过去时会重新加载一次。
- 浏览器地址是 `http://127.0.0.1:5300/`。以前的 `/vedic/`、`/western/` 书签仍然可用，会自动转到这里。按住 Ctrl 点体系按钮，会在新标签页里单独打开。

## 人物档案

### 档案库

- 点左上角的档案库名称打开菜单，可以切换、新建、重命名、删除档案库，或设置加密。
- 每个档案库是一套独立的人物、字段和标签，互不相干。
- 「删除档案库…」：选好要删的库，再输入一次它的名称确认。锁定的加密库也可以删，不需要密码。删除的文件不会马上消失，而是移到 `user_data/deleted_libraries/`，文件名后面加上删除时间。想找回时，关掉程序，把文件移回 `user_data/libraries/`，去掉名字里「__已删除-时间」这一段即可。确认不要了，再手动清空这个文件夹。

### 选择人物

- 点「选择人物…」打开列表，点一行即选中并排盘。
- 搜索框左边可选「名字」或「全文」。全文会在名字、标签和所有字段内容里查找，并显示命中的位置。
- 搜索框下面是「排序」：最近打开（默认）、名字、出生时间、最近修改、最近添加，以及每个数字或日期类型的字段。换排序依据时，方向会自动换成它常用的方向（时间类默认近的在前，名字默认正序），也可以再改。
- 排序每个档案库单独记住，关掉网页、重启程序后照样用。按最近打开、最近修改、最近添加或某个字段排序时，每行右侧会显示对应的时间或字段值。
- 「最近打开」指最近一次在列表里选中、或新建后用作本命盘的时间。打开网页时自动选回上次的人不算，切换占星体系也不算。只看盘、不改档案也会更新它。「最近修改」只在保存档案时更新。
- 鼠标移到列表中某一行时，右边会出现删除按钮，确认后直接删除这份档案，不必先选中再打开编辑窗口。删除不可恢复。
- 「筛选」可以按出生日期范围、标签、字段条件筛选。筛选和搜索不会被记住。「重置筛选」只清空筛选和搜索，排序不变。
- 列表底部可以导出或导入 CSV。导入时任何一行有错，整个导入都不生效。

### 编辑与新建

- 出生时间、时区、经纬度取自左侧「时间与地点」。名称、标签和自定义字段在浮窗里填写。
- 「保存」覆盖当前档案；「另存为新档案」保留原档案，另存一份；「删除」不可恢复。按 Ctrl + 回车也可以保存。

### 档案资料

选中人物后，结果区会出现「档案资料」标签页，显示这个人已填写的全部字段。

## 自定义字段

- 在「编辑档案」浮窗底部的「管理自定义字段」里增加、改名、改类型、删除字段。
- 字段类型：
  - 文本：可写长篇内容，最多 20000 字。
  - 数字、日期：可以按大小排序和按范围筛选。日期可写 `2020-05-12`、`2020-05` 或 `2020`。
  - 单选、多选：先定义好选项，可以按选项筛选。
  - 分组：自己不存内容，只用来收纳下级字段。
- 字段可以嵌套，最多 5 层。例如在分组「婚姻」下面放「婚姻状况」「结婚次数」「婚姻详情」。新建时在「上级」里选放在哪里；已有的字段改自己那一行的「上级」即可移动。
- 同一级里字段名不能重复，字段名里不能有「/」。排序、筛选和 CSV 里写完整路径，如 `婚姻/结婚次数`。
- 删除字段会同时删除所有档案里这一项的内容，连同它的下级字段，不可恢复。

## 档案库加密

- 加密按档案库分别设置，每个加密的库有自己的密码。入口在档案库菜单的「加密当前档案库…」。已加密时，这一项显示为「加密设置（取消加密 / 改密码）…」。
- 在这里可以加密、取消加密、立即锁定、更改密码，都只作用于当前档案库。
- 打开程序或切换到锁定的库时，会先弹出密码窗口。输入密码解锁，也可以在窗口里改用其他档案库。
- **不想每次输密码**：解锁后打开档案库菜单的「加密设置（取消加密 / 改密码）…」，输入当前密码，点「取消加密」。这个库就变回普通档案库，以后打开不再需要密码。取消加密不会改动任何档案内容。
- 加密的库在菜单里有一个锁形图标。
- 加密使用 SQLCipher（AES-256）。加密后速度与未加密时基本相同。
- **密码不保存在任何地方。忘记密码，这个档案库无法找回。** 请定期备份。
- 需要先安装 `sqlcipher3-wheels`（`pip install sqlcipher3-wheels`）。没装时其他功能照常。
- 导出的 CSV 是明文，请自行保管。

## 工具

在「计算设置」最下面的「工具」里。

- **结果标签页顺序**：调整星盘下方标签页的先后，点「完成」生效。两个体系各记一份。
- **原始参数**：查看当前这张盘后端返回的全部原始数值（不四舍五入），用来核对计算结果。可以一键复制 JSON。
- **导入 / 导出设置**：点开后选择要做哪一件事。
  - 导出：把两个体系的全部设置存成一个 JSON 文件。不含档案数据，也不含服务器地址。
  - 导入：选择导出的文件，替换当前设置，页面随后重新载入。别的项目组导入这个文件，就能用完全相同的设置起盘。

## 印度占星

### 计算设置

- **黄道体系**：恒星黄道（Sidereal）或回归黄道（Tropical）。星盘、KP、Dasha、分盘都在所选黄道的黄经上计算。
- **岁差体系**：只在恒星黄道下使用。KP 通常用 Krishnamurti，传统 Parashari 常用 Lahiri。
- **宫位制**、**月交点**（平交点或真交点）。
- **KP**：勾选「启用 KP」后计算 KP 行星、KP 宫位、KP 行星 ABCD、KP 宫位 1234 和 KP 主宰星，对应的标签页一起出现。KP 卜卦也在这一栏，KS-N 签号 1 到 249，CIL-N 签号 1 到 2193。卜卦只在启用 KP 时起作用。
- **分盘**：见下面的「分盘」一节。
- **Dasha**：见下面的「Dasha」一节。

### 星盘

- 星盘右上角切换北印度和南印度样式。
- 每个格子代表一个星座，度数是星座内度数。北印度盘最上方的菱形是上升星座。南印度盘星座位置固定，上升星座的格子左上角有一道斜线。
- 行星用两字母代码：Su 太阳、Mo 月亮、Me 水星、Ve 金星、Ma 火星、Ju 木星、Sa 土星、Ra 罗睺、Ke 计都。代码下有红线表示逆行。
- Asc 是上升点。非整宫制下，H1 到 H12 是各宫宫头，连同度数放进它所在的星座。H1 与上升点相同时只画 H1，不同时（如 Equal/MC 宫制）另外画出 Asc。
- 点一颗行星，高亮它投射相位的星座；点星座数字，高亮向这个星座投射相位的行星。相位按 Parashari 星座相位计算：所有行星看第 7 个星座，火星另看第 4、8 个，木星和罗睺、计都另看第 5、9 个，土星另看第 3、10 个。

### 分盘

星盘左上角是常用的几张盘：**Rashi**（本命）、**Transit**（过境）、**Moon**、**Bhava**、**D9**。其余分盘在旁边的「分盘」下拉菜单里，菜单里列出 BPHS 的全部 16 张分盘，每张写着编号、梵文名和主要看什么。当前看的是菜单里的某张盘时，菜单按钮显示它的编号。星盘上方有一行小字，写明当前这张盘的名称和所用算法。

- 分盘只在点到时才计算，算好后保留，直到本命盘重新计算，或这张分盘的设置改了。分盘再多也不会拖慢页面。
- 分盘只改变星盘。下方的结果表始终是本命盘的数据，切到 Transit 时才换成过境盘的数据。
- **Moon**：行星位置不变，以月亮所在星座为第一宫。
- **D 盘**：每个点（行星、罗睺、计都、上升点）按所选算法换算到分盘里。格内度数是它在这一份里走过的进度（换算到 0° 到 30°）。分盘不画宫头。
- **Bhava**：一个格子就是一个宫位，不再是一个星座。第 n 宫是从第 n 宫宫头到第 n+1 宫宫头的范围；Sripati 宫位制的宫头就是每一宫的起点（Sandhi）。格子的摆法与 Rashi 相同，第 1 宫放在上升星座的位置，格内数字照常是星座数字。点的度数照常是它在真实星座里的度数，宫头度数不画。鼠标停在点上会显示它在第几宫。相位按宫位数。

| D1 | Rashi | 本命 | 星座本身 | 无 |
| D2 | Hora | 财富 | 奇数星座前 15° 为太阳 Hora（狮子），后 15° 为月亮 Hora（巨蟹）；偶数星座相反 | Parivritti 循环法 |
| D3 | Drekkana | 兄弟姐妹 | 0° 到 10° 本星座，10° 到 20° 第 5 个星座，20° 到 30° 第 9 个星座 | Parivritti 循环法 |

动星座是白羊、巨蟹、天秤、摩羯；定星座是金牛、狮子、天蝎、水瓶；变星座是双子、处女、射手、双鱼。奇数星座是白羊、双子、狮子、天秤、射手、水瓶。Parivritti 循环法不分奇偶和动定变，从白羊起连续数下去，分盘黄经等于原黄经乘以分盘数后取 360 的余数。

### 分盘设置

在左侧「计算设置」的「分盘」折叠栏里，改了立即生效并保存。

- **Rashi 第一宫**：默认「跟随上升点」。选一个星座后，Rashi 盘以这个星座为第一宫（转宫），北印度盘整个旋转，南印度盘的斜线移到这个星座。Asc 仍然画在它真正所在的星座里。星盘上方会提示转宫到了哪个星座、上升点实际在哪个星座。转宫只改变 Rashi 星盘，结果表不变，Transit 也不转。
- **Bhava 宫位制**：Bhava 盘用的宫位制，默认 Sripati，可选的宫位制与上面的「宫位制」相同，两者互不影响。Bhava 宫位制与「宫位制」不同时，点开 Bhava 盘时会另外向后端要一次宫头（KP 卜卦开着时同样按签号定上升点）。
- **分盘算法**：点开后每张分盘一行，选用哪一种算法，下面写着这种算法的规则和出处。只有一种算法的分盘不能选择。「全部恢复默认」把所有分盘改回默认算法。折叠栏右侧会显示有几张分盘没有用默认算法。

### Dasha

#### 设置

在左侧「Dasha」折叠栏里。

- **起算行星**：从哪颗行星所在的星宿起算，默认月亮。所有体系共用。
- **一年的天数**：默认 365.25，可填 300 到 400。

#### 查看

- Dasha 标签页顶部的下拉框切换体系，切换时不用重新排盘。选过的体系会自动记住，下次打开先显示它。
- 先显示第一层，覆盖出生后约 120 年。当前所在的一段有底色和 ● 标记。

#### 各体系

都以起算行星所在的星宿决定出生时的第一位主星。出生时已走过的部分，按它在本主星所辖星宿里走过的比例计算。下级的分法都是从本段的主星开始，按各主星年数的比例循环一遍。

## 西方占星

### 计算设置

- **黄道体系**：回归黄道（Tropical）或恒星黄道（Sidereal）。所有点都按所选黄道计算。
- **岁差体系**：只在恒星黄道下使用。
- **宫位制**、**月交点**（平交点或真交点）。

### 星体配置

每一类点开一个浮窗修改。浮窗里的改动是草稿，点「完成」才保存并重算，点「取消」放弃。「恢复默认」恢复这一类的默认设置。

- **行星**：勾选要显示的行星和交点，每颗可以改颜色。这里还可以设置逆行标志 R 的颜色。
- **小行星**：输入 MPC 编号添加。主小行星以外的小行星需要放好对应的星历文件，例如 433 号放在 `common/astro/ephe/ast0/se00433s.se1`。
- **恒星**：默认 15 颗 Behenian 恒星。添加时输入 `sefstars.txt` 里的名称，如 `Regulus`。
- **Lot**：每个 Lot 有日间公式和夜间公式，夜间公式不填表示不分日夜。公式由几项相加减，可以引用行星代码（`Su`、`Mo` 等）、四轴（`Asc`、`MC`、`Desc`、`IC`）、宫头（`H1` 到 `H12`）、小行星 `#编号`、恒星 `*{名称}`、其他 Lot `@代码` 和常数度数。
- **特殊点**：远月点和近月点（平均、真实、插值）、朔望点、宿命点、反宿命点、东方点。
- **映点与反映点**：映点以巨蟹 0° 和摩羯 0° 为轴，反映点以白羊 0° 和天秤 0° 为轴。每一个可以单独启用、改符号和颜色。
- **星座配色**：12 个星座符号的颜色。

### 相位

#### 设置

- **行星选用**：哪些行星、小行星和四轴参与主相位表。
- **容许度**：每颗行星单独设置，其他点按组设置。两个点之间的容许度默认用古典半径法（两者各取一半相加），也可以取较大值或较小值。勾选「不与行星合成」的组，直接用本组的容许度。
- **相位类型**：默认合、六分、四分、三分、冲五种，可以新增。每种相位可以分别决定在主相位表和各组里是否计算。

#### 查看相位

- 点星盘右上角的「相位」，星盘位置换成相位表；点「星盘」换回来。边看盘边对照时不必上下翻页。
- 相位表上方切换「主相位表」和「特殊点 · 恒星 · Lot · 映点与反映点」。切回星盘再切回来，仍是上次看的那一张。
- 主相位表是三角矩阵。每格上面是相位符号，下面是离精确相位的偏差，A 表示入相，S 表示出相。
- 分组表每行一个相位，只列出有相位的组。

### 古典

- **先天尊贵**：各项分值（默认按 Lilly：入庙 +5、擢升 +4、三分 +3、界 +2、面 +1、失势 −5、入弱 −4、外来 −5）；三分主星体系（多罗修斯、托勒密或 Lilly）；三分怎么计分；界（埃及界或托勒密界）。
- **得时**：日生夜生按出生时太阳的高度判断（几何高度或视高度）。每颗行星可以设为日间派、夜间派或不参与。水星默认东出为日间、西入为夜间。
- **速度**：行星速度与哪一种平均速度比较（平均黄经运动、Lilly 传统值、1900 到 2100 年实际日行绝对值的平均，或自定义），以及按速度大小还是按带正负号的速度比较。
- **太阳光束**：可以自定义若干档，每档一个名称和一个度数，最多 6 档。默认 17′ 以内为日核，8.5° 以内为焦伤，17° 以内为光束下。名称可以改，比如把「焦伤」改成「灼伤」。行星与太阳的距离落在哪一档，就在行星表的「日照」一栏显示那一档的名称。

### 星盘

- 第 1 宫宫头固定在正左边，黄道度数沿逆时针增加。
- 最外圈是各宫宫头的星座度数。往里一圈是与行星构成相位的恒星（✦），点一下显示详细信息。
- 中间是行星、小行星、特殊点和 Lot。每个元素沿一条射线排开：符号、度、星座、分、逆行标志 R，字号依次变小。内圈的短刻度标出每个元素的真实位置。
- 点一个元素，与它构成相位的元素高亮，其他变淡。再点一次或点空白处取消。鼠标停在元素上，显示它的位置和全部相位。

### 结果表

- 星盘下方的标签页：行星、宫位、值日星 · 行星时、小行星、恒星、Lot、特殊点、映点与反映点、档案资料。没有启用任何一项的类别不显示。
- 行星只写符号。黄经写成星座符号加星座内度分秒；黄纬、赤经、赤纬也用度分秒；速度用小数（°/日）。

- **小行星、特殊点**：黄经、黄纬、赤经、赤纬、速度。**恒星**另有星等和拜耳命名。

## 文件与备份

- 所有用户数据都在 `user_data` 文件夹里。备份时先关闭程序，再复制整个文件夹。
- `user_data/libraries/`：每个档案库一个 `名字.sqlite3` 文件。程序运行时旁边会有 `-wal` 和 `-shm` 两个文件，属正常现象，不要单独删除。
- `user_data/deleted_libraries/`：删除的档案库放在这里，可以找回。
- `user_data/settings.json`：全部设置。网页上的改动会自动写入；手工修改后需要重启程序。`server` 一节可以改端口。
- 档案库为几十万份档案设计。20 万份档案时，翻页、排序、打开和保存一份档案都在 5 毫秒以内，筛选和全文检索一般在 0.1 到 0.3 秒。
- 星历使用 Swiss Ephemeris 的星历文件，放在 `common/astro/ephe`。缺少某个文件时，结果表下方会写明缺哪一个。

## 给开发者

### 目录

```
app.py              启动入口
common/             共用区：天文基础（星历、宫位、日出日落）、人物档案（前后端）、设置、页面外壳
systems/vedic/      印度占星（KP、Dasha、南北印度盘、分盘）

user_data/          设置和档案库（不属于代码，备份时连同它一起备份）
```

- `systems/` 下的体系是自动发现的。删掉某个体系的文件夹，程序照常运行，只是少了那个体系。
- common 里的代码不 import 任何体系；体系之间也互不 import，只通过 `common/system.py` 的 `AstroSystem` 挂进来。
- `python tools/export_system.py vedic`（或 `western`）把一个体系连同共用区打成 zip，交给只维护这个体系的组。

### 星盘视图与分盘基底（common/static/common.js）

体系的前端用 `registerSystem({...})` 挂进共用页面。和星盘视图有关的挂接点：

- `viewLabels`：改写本命、过境两个按钮的名称（印度占星改成 Rashi、Transit）。
- `derivedViews`：从本命盘换算出来的分盘，`{键: {label, derive, signature, bar}}`。
  - `derive(本命结果, {payload})` 只在点到这张盘时才调用。可以直接返回结果，也可以返回 Promise（需要向后端要数据时，例如 Bhava 盘）。返回 Promise 时先显示「计算中…」。
  - `signature()` 返回这张分盘自己的设置（如算法名）。它变了，缓存就失效，下次显示时重新换算。
  - `bar: false` 表示不放在按钮条上，只出现在下拉菜单里。
- `viewMenu`：按钮条右边的下拉菜单，`{label, items: [{value, label, note, sub, title}]}`。分盘再多，页面上也只多一个按钮。
- `viewCaption(视图, 结果)`：星盘上方的一行说明。

换算结果按「本命结果 + signature」缓存在 `state.derived`，没点到的分盘永远不计算，所以分盘数量不影响页面速度。

### 怎样加一张分盘，或给分盘加一种算法

分盘的规则全部登记在 `systems/vedic/static/vargas.js`，菜单、算法浮窗、星盘说明都从这里自动生成，不需要改别的文件。

- 加一种算法：在那张分盘的 `methods` 里加一项 `{label, source, note, toLon}`。`toLon(黄经)` 返回分盘黄经（0° 到 360°）。文件里有现成的工具函数：`equalParts`（等分，连续往后数）、`mappedParts`（等分，每份直接指定星座）、`unequalParts`（不等分）、`cyclic`（循环法）。算法的键只能用小写字母、数字、`_` 和 `-`，它会写进 `settings.json`。
- 加一张分盘（例如 D5、D81、D108）：在 `VARGAS` 里按同样的格式加一项。
- 也可以在另一个文件里调用 `VedicVargas.addMethod(分盘, 键, 算法)` 或 `VedicVargas.register(分盘)`，这个文件要在 `vargas.js` 之后、`vedic.js` 之前加载。
- 每张分盘的第一种算法是默认算法。设置里保存的算法被删掉时，自动退回默认算法。
- 想把另一张 D 盘放到按钮条上，改 `systems/vedic/static/vedic.js` 里的 `PINNED_VARGAS`。

### 印度占星的接口（/vedic/api/）

- `POST /chart/full`：排盘。
- `POST /bhava`：Bhava 盘的宫头。请求与 `/chart/full` 相同，另加 `house_system`。
- `POST /varga`：保存分盘设置（`rashi_lagna`、`bhava_house_system`、`methods`）。
- `POST /calc-defaults`、`POST /chart-style`、`POST /dasha/expand`。

分盘设置保存在 `settings.json` 的 `systems.vedic.varga`：

```json
"varga": {
  "rashi_lagna": "asc",
  "bhava_house_system": "Sripati",
  "methods": {"D2": "parivritti"}
}
```

`rashi_lagna` 是 `"asc"`（跟随上升点）或 0 到 11（白羊到双鱼）；`methods` 里只写没有用默认算法的分盘。
